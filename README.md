# Xsee · 星雨图片查看器

一款 Windows 上的本地图片浏览与整理工具。窗口全部自己画——标题栏、菜单、弹层、缩略图格子、对话框都不依赖任何 UI 框架，配色、图标整套可换。

一款 Windows 看图软件。界面布局照 ACDSee 3.0 那一套重排了一遍——作者用它很多年，熟那一套手感。在看图之外加了三样：图片管理（按类别把图归起来）、以图搜图（找长得像的图）、参考图画布（把图浮在别的软件上当对照）。

里面有哪些功能、支持哪些文件格式，都是按作者自己日常要用到的那些定的，这不是一个长期开发的项目：现在这份就是最终版。想要更多功能、要额外的文件格式支持，或者碰到了 bug，建议自行下载源码修改，欢迎 fork。

---

## 能做什么

**浏览**  
文件夹树 + 四档视图（缩略图 / 图标 / 列表 / 详细资料），双击进查看态。缩放、平移、框选放大、旋转翻转、翻页、前后退历史；按名称、扩展名、大小、类型、日期、图像属性、入库时间、描述排序。

**图片管理**  
一张图可以同时挂在几个类别下面，类别分上下级，同级自己排序。分类记录存本地库，能统计、检查、导出、导入。批量重命名有独立对话框，也能原地改。

**以图搜图**  
按感知哈希在本地找长相接近的图。**指纹只从已经生成的缩略图算，不打开原图**，所以搜一库几万张图不去碰硬盘上的大文件。结果页可以调相似度、选要不要连镜像和旋转过的一起找。

**参考图画布**  
一块置顶、背景能透的画布。图各自拖、各自缩放，剪贴板里的图或文件可以直接贴进来。做设计、选素材时把它浮在别的软件上面当对照。

**编辑图像**  
独立的编辑窗：裁剪、调整大小、旋转翻转、色阶、色调饱和度、颜色均衡、曝光、模糊与锐化、去斑点。改完可以覆盖原文件或另存。

**批量**  
JPEG / PNG / BMP / TIFF / GIF 互转，每个格式各存一份自己的质量设置；批量重命名；在当前文件夹或整库里按名字搜。

**文件关联**  
把 Xsee 登记成图片格式的「打开方式」候选，每种格式配一张自己的图标牌（不是共用一个通用图标）。启动时会复查一遍这些登记，被别的程序或清理工具抹掉的会补回来。

**外观**  
皮肤 24 套（浅色 / 深色 / 莫兰迪 / 撞色系列，一个色系一个文件夹），配色和每块字号都能自己改，改完只覆盖在你本机。版式 47 套开源图标库可换，同样走文件：`skins\图标\` 下一套一个 `.icons`。`skins\` 目录 exe 旁边有就用它，没有就用 `%LOCALAPPDATA%\xsee\skins`，设置窗里也能单独指定。

**格式**  
JPG、PNG、BMP、GIF、TIFF、ICO、WebP、PSD、AVIF、TGA、DDS、QOI、EXR、HDR、PNM（PBM / PGM / PPM / PAM）、JPEG XR（WDP / HDP / JXR），以及常见的 RAW（NEF / CR2 / CR3 / ARW / RW2 / DNG / ORF / RAF / PEF / SRW / X3F / 3FR / FFF / IIQ）。HEIC 和 AVIF 走系统解码器，装了相应扩展的机器上才出图。

## 上手

从 [Release](https://github.com/cooloop88/Xsee/releases/tag/v0.1.0) 下载解压就能用，**不需要安装、不需要管理员权限**。

```
xsee\
  xsee.exe          浏览窗口
  xedit.exe         编辑窗口（浏览窗口里的编辑图像要用它，两个放同一个文件夹）
  skins\
    图标\           47 套版式图标，一套一个 .icons
    皮肤\           24 套皮肤，按色系分文件夹
```

把整个文件夹放哪都行。有三个小坑：

- **第一次运行会弹蓝框**。这个 exe 没有购买代码签名证书，从浏览器下载下来会带上"来自 Internet"的标记，Windows 可能拦一次 SmartScreen。点「更多信息」→「仍要运行」就过去了，之后不再拦这个文件。这是没有 OV/EV 证书的正常现象，不是包被改过。
- **别放在桌面根目录运行**。Windows 会把桌面下的文件按"从网上下载"处理，双击时弹一句"无法验证发布者"——这是系统对新文件的例行提示，不是软件问题。放 D 盘、E 盘或桌面下的子文件夹都不会弹。
- 想让它成为双击图片的默认程序：软件里勾完关联后，仍然要在系统的「默认应用」设置里按文件类型选一次 Xsee。Windows 10/11 不允许任何程序静默改这一层，这不是本软件能绕过的。

## 数据放在哪

| 内容                               | 位置                            |
| -------------------------------- | ----------------------------- |
| 分类库、格式转换设置                       | exe 旁边的 `data\`（第一次建类别时才创建）   |
| 缩略图缓存、版式偏好、每套皮肤的个人改动、搜图指纹库       | `%LOCALAPPDATA%\xsee\thumbs\` |
| 皮肤（exe 旁没有 `skins\` 时）           | `%LOCALAPPDATA%\xsee\skins\`  |
| 界面状态（当前皮肤、视图档、排序、窗口尺寸、上次目录、关联清单） | 注册表 `HKCU\Software\Xsee\UI`   |

缓存目录可以用环境变量 `XSEE_CACHE_DIR` 指到别处。**删掉上面这些就等于清空全部本地记录**——软件不联网，不含任何云端服务，不会上传任何东西。

## 性能

**测试条件**：下面每一个打开／出图的数字，图都在**一块 16 TB 企业级机械硬盘**上（东芝 MG08ACA16TE，SATA 7200 转级）。机械盘的短板正是随机读小文件，所以这些应当看作保守值——同一批图放固态硬盘上只会更快。

### 一、第一次进一个没缓存过的文件夹（缩略图逐张出）

套件：1038 张 JPEG，合计 **15.39 GB**，**平均 15.1 MB／张**（大幅效果图和贴图，不是手机小图）。

| 口径            | 数字                                    |
| ------------- | ------------------------------------- |
| 单线程顺序         | **187 毫秒／张**（5.3 张／秒）                 |
| 8 线程          | **10.9 张／秒**                          |
| 纯解码管线（关掉缓存写入） | 150 张 3.80 秒 ≈ **41 张／秒**，单张摊销 193 毫秒 |

- 这个速度是**被机械盘的读盘顶住的**，不是 CPU 算不过来；并发加到 8 个 worker 只换来约 2 倍，原因就在这。
- 缩略图只解到目标尺寸（内接 173×119 那一档），不会先把几十 MB 的原图整张读进内存——这是内存能压住的原因。
- **第二次进同一个文件夹读本地缩略图库，一张原图都不解。**

### 二、双击打开一张图（墙钟时间）

每种格式挑那块盘上**最大的一张**，所以这是最坏情况，不是典型情况：

| 格式       | 原图像素        | 文件大小               | 出缩略图     | 出屏幕大小   |
| -------- | ----------- | ------------------ | -------- | ------- |
| BMP      | 4420×6363   | 107 MB             | 39 ms    | 71 ms   |
| GIF（动图）  | 720×960     | 40 MB              | 4 ms     | 7 ms    |
| HEIC     | 5712×4284   | 2.3 MB             | 558 ms   | 822 ms  |
| ICO      | 512×512     | 1 MB               | 2 ms     | 3 ms    |
| JPEG     | 10000×4908  | 58 MB              | 467 ms   | 595 ms  |
| JPEG（超大） | 14960×22440 | **497 MB／3.3 亿像素** | **1 ms** | 3627 ms |
| PNG      | 8000×5600   | 233 MB             | 3202 ms  | 3264 ms |
| PSD      | 5906×4725   | **1.1 GB**         | 1 ms     | 189 ms  |
| TIFF（超大） | 12976×25952 | **1.93 GB**        | 1367 ms  | 1410 ms |
| WebP     | 350×350     | 3.6 MB             | 26 ms    | 27 ms   |

**普通尺寸的 JPEG（几 MB 到十几 MB 那种）出屏幕图约 0.6 秒**，这是日常看图的真实体感；上面那一档 3.6 秒是 3.3 亿像素的极端样本。

两点如实说明：

- **PNG 慢是格式本身决定的**：PNG 没有缩放解码，要 173 像素还是 8000 像素都得整张解开，所以大 PNG 一律 3 秒上下。JPEG 能"缩着解"，497 MB 那张出缩略图只 1 毫秒（直接吃文件里内嵌的小预览）；PSD 走的是自己解合成图那条路，1.1 GB 出屏幕图 189 毫秒；1.9 GB 的 TIFF 也只用 1.4 秒，比同像素的 PNG 还快。
- **HEIC 依赖系统解码器**：装了 HEVC 扩展的机器才出图，而且第一次开档要多约 0.3 秒加载解码器。

### 三、内存

| 情形                    | 实测                                |
| --------------------- | --------------------------------- |
| 正常看图（只出屏幕大小）          | 进程峰值 **118 MB**，单张屏幕位图约 14 MB     |
| 原尺寸全解那张 3.3 亿像素的 JPEG | 1.3 GB——这是"原尺寸全解"那一档，浏览时不会走到      |
| 缩略图驻留池                | 攒到 **600 张**触发回收，常态常驻约 **1050 张** |

### 四、界面响应

- 冷启动到界面画完 **0.1–0.4 秒**：全新路径首次 387 ms，同一目录重复 119–120 ms，热盘上的真实目录 105 ms。慢的时候不在程序里，在冷机械盘扫目录和逐级展开左树。
- 缩略图滚动单帧 **15.8 毫秒**（老写法整窗重绘要 93 毫秒）。靠三条：常驻后备位图 + `ScrollDC` 平移复用已画内容、只补画新露出的条带；缩略图解好之后 1:1 拷贝，滚动帧不再重缩放；帧驱动用可等待定时器自走节拍（`SetTimer(33)` 会被系统合并到约 48 毫秒，所以没用它）。

### 五、和几个看图软件的对照

同一台机器、同一批图（那块机械盘），各测一轮。**口径不完全一样，看之前先对齐最后一栏**：

|               | 每张图的成本               | 并发度        | 内存峰值     | 第二次进同一文件夹       |
| ------------- | -------------------- | ---------- | -------- | --------------- |
| ACDSee 3.1    | 0.86 CPU 秒／张         | 约 2 个核     | 80–97 MB | 读它自己的缩略图库，一张都不解 |
| nomacs 3.22.4 | 名义 0.42 CPU 秒／张      | 约 22 个核    | 8.5 GB   | 全部重解            |
| Xsee          | 187 ms／张（**墙钟**，单线程） | 8 个 worker | 118 MB   | 读本地缩略图库，一张都不解   |

Xsee 那一格给的是墙钟不是 CPU 秒，跟前两行不能直接比大小；可以直接比的是内存峰值，以及"第二次要不要重解原图"。nomacs 那两栏是它默认设置下的表现（线程多、不做缩放解码），不是它的缺陷，只是设计取舍不同。

## 从源码构建

只在 Windows 上构建，需要 Rust（edition 2024，1.85 以上）和 Windows SDK。代码在仓库的 `host\` 目录里，进去跑：

```
cargo build --release --bin xsee      # 浏览窗口
cargo build --release --bin xedit     # 编辑窗口
```

产物在 `target/release/`。**界面用的 `skins\` 不会自动跟着编译产物走**：把仓库根目录的 `skins\` 复制到 exe 旁边，47 套版式和 24 套皮肤才会出现在菜单里；不拷也能跑，exe 里编了一套 Lucide 图标和一套兜底配色顶着。`skins\` 里的文件改了下次启动就生效，不用重编译。发布用的二进制开了 strip 和 thin LTO（见 `Cargo.toml` 的 `[profile.release]`），比默认 release 配置小一圈。

`build.rs` 调 Windows SDK 自带的 `rc.exe` 把图标编进 exe；没有 `rc.exe` 时只报一条警告并跳过图标，程序照常能跑。

直接依赖只有 7 个 crate：`image`、`jpeg-decoder`、`jpeg-encoder`、`tiff`、`crossbeam-channel`、`windows`、`windows-core`，其余是它们的传递依赖。界面不挂任何 UI 框架，Win32 调用全走 `windows` 这套绑定。`src\bin\` 下除了这两个正式窗口，还有一批开发期用的命令行探针（解码计时、图标生成、库检查等），不参与发布，可以忽略。

## 已知边界

- 只支持 Windows。窗口全部自绘，因此高 DPI 缩放的观感是自己一套规则，不是系统控件的默认表现。
- 不能替用户把 Xsee 设成文件类型的默认程序，系统那一层锁着（见上面「上手」）。
- 搜图阈值目前是写死的，界面上还没做成可调；「查找转过的／镜像的」在界面上有开关，取最小汉明距离那套优化已经实测过但没接进主流程。
- 软件图标是字标，32 像素以下会发糊——这是字形本身决定的，不是压缩坏的。
- 不连接任何在线服务，也不做云同步。分类库是自己的一份 `catalog.tsv`，导入导出只认它；布局参考 ACDSee 3.0，除此之外不含它的任何代码和文件，不读它的数据库，也不要求机器上装过它。
